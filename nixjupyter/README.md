# nixjupyter — JupyterLab (CT 117)

Personal JupyterLab with the notebooks that ran on the old server.

* URL: <https://lab.minnecker.com> (wildcard cert, proxied by `nixnginx`)
* Container: `nixjupyter`, CT **117**, `10.20.20.27` / `fd01::27`, rootfs
  `fast:20G`, 2 cores / 4 GB
* App: `jupyter-lab` (JupyterLab 4.5, Python 3.13) from a pinned
  `python3.withPackages` environment — no `services.jupyter` module exists in
  nixpkgs, so the unit is written out in [`jupyter.nix`](jupyter.nix)
* Files: `/var/lib/jupyter/work`, covered by the nightly restic pass through
  `vzdump 117`

## What came over

The notebooks were rescued off saver CT 107 on 2026-11-22 into
`/var/lib/px-archive/saver-2026-11-22/restored/jupyter/work` on `px`, and that
tree is what this container starts from:

| | |
| :--- | :--- |
| files | 199 |
| notebooks | 42 |
| size | 229 MB |
| newest edit | 2024-05-19 (`bsc/Untitled.ipynb`) |
| oldest | 2020-02-25 |

`work/ju.tar` and `work/ju_bak.tar` (~500 MB of older snapshots) were deliberately
left inside `jupyter-work.tar.gz` rather than unpacked next to the tree; they are
still in the archive and in the pinned `archive`-tagged restic snapshots.

### Why these python packages

The environment is the set of third-party modules the 42 notebooks actually
import, measured over every cell of every notebook:

```
matplotlib 38   numpy 30   pandas 26   tabulate 12   seaborn 4
Bio (biopython) 4          sklearn 2   plotly 1
```

Everything else in those notebooks was stdlib. `statsmodels` and `sympy` are the
only additions, because they are the two things a notebook of this kind reaches
for next and are already in the binary cache.

## Secrets

| What | Where | Notes |
| :--- | :--- | :--- |
| Access token | `/var/lib/jupyter/state/token` | generated by `jupyter-secrets.service` on first start, mode 600, never in the Nix store |
| — | — | no database: Jupyter keeps no state beyond these files |

Read it with:

```bash
pct exec 117 -- cat /var/lib/jupyter/state/token
```

and open `https://lab.minnecker.com/?token=<token>`. The token is copied into
`/run/jupyter/env` at start and consumed by
[`jupyter-server-config.py`](jupyter.nix) via `os.environ["JUPYTER_TOKEN"]` —
deliberately a hard lookup, so a missing token aborts the service instead of
starting an unauthenticated code-execution server.

Rotation: delete the token file and restart `jupyter.service`; the oneshot mints
a new one.

## Create the container

```bash
pct create 117 local:vztmpl/nixos-image-lxc-proxmox-26.05pre-git-x86_64-linux.tar.xz \
  --hostname nixjupyter --ostype nixos --unprivileged 1 --features nesting=1 \
  --storage fast --rootfs fast:20 --cores 2 --memory 4096 --swap 2048 \
  --onboot 1 --startup order=2 \
  --net0 name=eth0,bridge=vmbr1,gw=10.20.20.1,gw6=fd01::1,ip=10.20.20.27/24,ip6=fd01::27/64
```

No `lxc.mount.entry` lines — nothing is shared with other containers.

Then bootstrap per the root README (clone to `/root/nixos-config`, symlink
`configuration.nix`/`common-lxc.nix`/`hosts.nix` into `/etc/nixos`, rebuild),
and seed the notebooks **before** the first start so the history is intact:

```bash
mkdir -p /var/lib/jupyter/work
cat /tmp/jupyter-work.tar | tar -C /var/lib/jupyter/work -xf - --no-same-owner
chown -R jupyter:jupyter /var/lib/jupyter
```

## Differences from the old deployment

| | old (saver CT 107) | new |
| :--- | :--- | :--- |
| runtime | podman + `quay.io/jupyter/datascience-notebook` | `jupyter-lab` from nixpkgs, no container runtime |
| reachable | plain HTTP on host port 8004, LAN only | `https://lab.minnecker.com` through nixnginx |
| token | `JUPYTER_TOKEN` hard-coded in `docker-compose.yml` | generated at first start, mode 600 |
| packages | whatever the upstream image shipped | pinned to what the notebooks import |

## Websockets

Jupyter drives kernels and terminals over websockets on the same port as the UI
(`/api/kernels/.../websocket`, `/terminals/websocket/websocket`). The vhost in
`nixnginx` therefore sets the `Upgrade`/`Connection` headers on `locations."/ "`
and raises `proxy_read_timeout` — nginx's 60 s default otherwise kills an idle
kernel connection and the notebook shows "kernel disconnected" once a minute.
